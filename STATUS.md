## 2. Keputusan Penting

- **Kesepakatan final pengguna (menggantikan arah sebelumnya):** Pertahankan AuthN dan RBAC terpusat existing, termasuk syarat role aplikasi pada login/refresh/verify, JWT role/permission, serta pengelolaan akses portal. Tidak membuat UserClientApps pengganti. Tambahkan profil pegawai/organisasi opsional; mutasi/promosi/acting tidak mengubah role otomatis. Scope transaksi dan approval tetap milik konsumen. Blueprint baru melengkapi, bukan mengganti, PLANNING.md/PLANNING_FRONTEND.md.
- **D-01 dan D-03 disetujui pengguna pada awal implementasi:** master pegawai di auth-api, link opsional 1:1, nama akun dan nama resmi pegawai dibedakan; Asia/Jakarta, awal periode inklusif/akhir eksklusif; tanggal resign adalah hari pertama nonaktif; koreksi backdate ditunda dari rilis awal.
- **D-02 dan D-04 disetujui setelah provisioning kantor:** ACTIVE/RESIGNED, resign efektif menolak login/refresh, aktivasi kembali manual, role tetap tersimpan, unlink/relink dilarang saat ada resign berlaku/terjadwal; pimpinan max1 definitif, Pelaksana multi, fungsional configurable, satu utama plus rangkap, PLH/PLT wajib SK/periode tanpa automatic permission. Ini keputusan untuk implementasi P2/P4, belum perilaku runtime yang tersedia.
- **Scope awal D-05 disetujui:** empat template operasional draft. Kode unit/posisi adalah usulan teknis; ROOT kontainer OTHER. Semua level null hingga master resmi dipetakan. Struktur pusat dan hubungan antarkantor ditunda. Katalog tunggal `data/organization/operational-templates.v1.json`; generator file-only `scripts/New-OperationalTemplateProvisioning.ps1` menghasilkan SQL manual. Draft belum dipublish atau diaplikasikan ke kantor.
- **D-06 disetujui pengguna (2026-11-06):** permission `employees.*`/`organization.*` granular, rilis awal dipetakan hanya ke SuperAdmin internal `auth-admin` (selaras dengan guard mutasi P2B); `employees.history.read` terpisah dari `employees.read`; `users.read/write` tidak memberi hak pegawai; directory lintas user dan role HR terpisah ditunda. Dasar untuk P3.
- **Revisi P2A:** Id penempatan/acting adalah row revisi, AssignmentKey adalah identitas logis. Filter unique satu current revision per key, unique key+revision untuk histori. Acting.SourceEmployeePositionId menunjuk row definitif exact dengan FK komposit EmployeeId. DRAFT hanya assignment baru pada baseline; tidak boleh menyupersede confirmed dengan draft. P2B wajib merevisi sumber dan seluruh acting current yang terpengaruh secara atomik atau menolak perubahan. Kapasitas menghitung versi posisi efektif, bukan kapasitas hari ini saja.

## 3. Masalah yang Diketahui

1. **P2A schema belum diterapkan:** Master kantor/template draft telah dikonfirmasi. Pondasi Employee/Status/Position/Acting/Link dan validasi domain tersedia pada kode, tetapi migration baru menunggu pengguna. Use-case mutasi/transaksi/audit, validasi status/struktur lengkap, API, guard, lifecycle dan portal belum dibuat. Aturan murni tidak memberikan jaminan konkurensi runtime tanpa use-case P2B.
   - Kendala Windows Authentication dan sintaks WITHOUT_ARRAY_WRAPPER pada provisioning sebelumnya sudah teratasi melalui SQL Authentication oleh pengguna dan koreksi file script. Keberhasilan 5/28/28 tidak membuktikan semua constraint/race telah diuji. Versi/compatibility level server tidak diinspeksi atau diasumsikan.
2. **Batas revokasi existing:** Verifikasi realtime membaca akses terbaru, tetapi filter admin memakai klaim JWT. Belum ada access version pada JWT dan pengecekan versinya. Pencabutan refresh token tidak otomatis membatalkan JWT yang masih valid pada konsumen dengan validasi lokal saja.
3. **Keputusan bisnis terbuka:** detail D-05 (struktur pusat, hubungan antarkantor, master/pemetaan level dan reorganisasi), D-06 (akses profil/history), D-07 (SLA/scheduler) dan D-08 (retensi). BRD tetap DRAFT. Struktur pusat/induk kantor tidak boleh dikarang; approval/fallback tetap tanggung jawab konsumen. D-01/D-02/D-03/D-04 dan scope draft D-05 sudah disetujui.
6. **Temuan review P3A (2026-11-06):** tidak ada bypass autentikasi/IDOR/cache. Diperbaiki: field enum/bool wajib yang hilang tidak lagi diam-diam jadi default (nullable + `[Required]`, mencegah reaktivasi tak sengaja), batas `page` (cegah overflow Skip), `DbUpdateConcurrencyException` → 412, 4xx dicatat sebagai Warning tanpa stack trace. **Masih terbuka:** (a) rate limit berjalan sebelum autentikasi sehingga dipartisi per IP; di belakang BFF semua admin berbagi satu bucket kecuali `ForwardedHeaders` + `KnownProxies` dikonfigurasi benar saat deployment; (b) pesan `InvalidOperationException` mentah (termasuk pesan framework/EF) dikembalikan sebagai 409 — pertimbangkan exception domain khusus; (c) respons enum berupa angka sedangkan request memakai string — keputusan kontrak (jangan ubah global karena memengaruhi endpoint lama); (d) `DELETE …/employee-link` membutuhkan body JSON (alasan) yang dapat dibuang proxy/BFF; (e) `assignmentId`/`actingId` di route adalah Id revisi row (berubah setiap revisi), bukan `AssignmentKey` stabil — klien harus mengambil ulang detail setelah tiap mutasi.
5. **Temuan review P2B yang masih terbuka:** (a) ~~kebijakan reaktivasi~~ diputuskan pengguna 2026-11-06: ACTIVE setelah RESIGNED **diperbolehkan** (sesuai D-02 aktivasi kembali manual); penempatan yang sudah ditutup tidak dibuka otomatis, test `ChangeStatus_AllowsManualReactivationAfterResignation`; (b) ~~visibilitas~~ selesai: konstruktor `AuthorizedEmployeeMutation` kini `internal` sehingga kode di luar assembly Application tidak bisa memalsukan otorisasi; `IEmployeeScheduleWriter` tetap publik karena dipakai konstruktor service publik; (c) ~~validasi global~~ selesai: `ValidateAsync`, `AssignDefinitive`, dan penutupan resign kini dibatasi ke data pegawai terkait plus penempatan lain pada posisi yang sama (hanya untuk kapasitas); (d) ~~audit~~ selesai: detail terstruktur >4000 karakter kini disimpan sebagai JSON valid `{truncated, originalLength, preview}`; string mentah tetap dipotong. Perapihan ini (build 0 warning/0 error, test 61/61) belum ditinjau ulang secara independen.
4. **Keterbatasan verifikasi:** Test metadata memakai provider SQL Server tanpa membuka koneksi; constraint/locking riil harus diperiksa pengguna di database pengujian terpisah. EF CLI terpasang `10.0.12` memberi peringatan lebih lama dari runtime `10.0.14`; generation dan pemeriksaan snapshot offline berhasil. Tidak mengubah instalasi tool global.
